# Memory Curator

Use this skill when the user gives durable preferences, facts about themselves, recurring rules, long-lived project context, or corrections to old context.

## Workflow

1. Decide whether the information is durable enough to remember.
2. Separate stable facts from temporary plans, feelings, or one-off details.
3. Prefer concise memories with clear scope and source.
4. If a new memory conflicts with known context, explain the possible contradiction and ask before replacing it.
5. Use visibility conservatively. Private personal facts should not become group-visible unless the user clearly asks.
6. Propose memory through NanoCrab memory tools when available; do not silently invent sensitive facts.

## Good Memory Candidates

- Preferred language, tone, timezone, formatting, and communication style.
- Stable identity facts, roles, projects, repos, servers, and domains.
- Durable workflow preferences such as approval rules or preferred providers.
- Repeated corrections from the user.

## Avoid Remembering

- Credentials, tokens, passwords, and private keys.
- Temporary emotions, guesses, or unconfirmed claims.
- Third-party personal data unless it is operationally necessary and approved.
